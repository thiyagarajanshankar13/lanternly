How it works

Three steps from an empty VM to a deployed app.

  1. 1

    Add a server

    Run one setup script on any Ubuntu VM. The console reaches it over SSH with a key that can only run the deploy tool, never a shell.

  2. 2

    Connect GitHub

    Install the GitHub app on your repos. Any branch with a Dockerfile can be deployed, built for free on GitHub Actions.

  3. 3

    Push to deploy

    Every push builds, runs your migrations and goes live once the health check passes. If it fails, the previous version keeps running.

Everything in the box

The parts of a hosting platform you'd otherwise glue together yourself.

Deploy from GitHub

Any repo and branch with a Dockerfile. Versions are commits, and Roll back starts an earlier one without rebuilding.

Or any Docker image

Docker Hub, ghcr.io or a private registry. Tags are pinned to the exact digest that was pulled.

Projects with private networks

Group an app and its database. Services find each other by name, and projects can't see each other.

PostgreSQL, looked after

One tick links it to an app. Password rotation, upgrades by dump and restore with roll back, and a size quota with alerts.

HTTPS and your domains

Every service gets an address under your domain with a free certificate. Point a CNAME to add a custom domain.

Encrypted backups to any S3

AWS, Backblaze B2, Cloudflare R2, MinIO. Encrypted before upload, on a schedule, and restorable to a copy first.

Monitoring and alerts

Uptime, speed, versions and certificate expiry, for your services and any site hosted elsewhere. Emails when something breaks.

Team access

Owners, operators and viewers, per project or per service. Invites by link, and a year of access log.

Plugins

Add service kinds, pages and settings. The AWS plugin creates servers from the console and shows what AWS charges you.

Small and boring, on purpose

Two VMs, one SSH key, no agents phoning home.

  • The console's SSH key is locked to one command on each server, and a changed host key is refused.
  • Database passwords are made on the server and never leave it.
  • App secrets and bucket keys are stored encrypted (AES-256-GCM) and masked in logs.
  • Everyone signs in with a password and an authenticator app. No exceptions.

Quick start

What you need

  • Two Ubuntu 24.04 VMs with Docker and a static IP
  • A domain whose DNS you control
  • A GitHub account (for app builds)
  • An S3-compatible bucket, if you want backups

terminalbash
# 1. DNS: admin.example.com and *.example.com
# 2. On the deployer VM
sudo DEPLOYER_DOMAIN=admin.example.com ./setup-deployer-vm.sh

# 3. On each services VM
sudo DEPLOYER_PUBLIC_KEY="ssh-ed25519 AAAA…" \
     ACME_EMAIL=you@example.com ./setup-clubs-vm.sh

# 4. Open the console and sign in
open https://admin.example.com/admin
