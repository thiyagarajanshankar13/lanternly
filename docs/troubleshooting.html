Troubleshooting

Most problems show up in a service's History, where every operation keeps its full output. Start there.

#Servers and SSH

#"Host key doesn't match"

The server presented a different SSH host key from the one saved. If you rebuilt the VM, that's expected: open Servers → Edit and paste the new key printed by the setup script. If you didn't, stop and find out why before going further.

#Can't connect to a server

  • Check port 22 on the server allows the deployer VM's IP.
  • Check the setup ran with the right DEPLOYER_PUBLIC_KEY (the one under Servers).
  • The SSH user is always deployer, not ubuntu or root.

#"Not enough room on the server"

The memory already given out on that server plus the new service's limit is over the server's figure. Lower some memory limits, raise the server's figure if it really has more RAM, or add a server.

#A new command is refused

The server has an older clubctl than the console expects. Run the services setup again (see Update clubctl).

#Apps and builds

#The build fails

Open Builds → GitHub log. The usual causes: the Dockerfile path is wrong, the GitHub App isn't installed on the repo, or the Lanternly repo is missing the build secrets (the GitHub page says so). A failed build never touches the running version.

#"No build started"

The build workflow didn't start within 5 minutes. Check that .github/workflows/build-app-image.yml is on your copy's default branch and that Actions are enabled there.

#Pushes don't deploy

  • Check Deploy every push to the branch by itself is ticked in the app's Settings.
  • DEPLOYER_URL must be the console's public https:// address. In the GitHub App's settings, Advanced → Recent deliveries shows whether GitHub reached it.

#The new version is rolled back

It didn't answer its health page within 2 minutes. Check the port the app listens on matches the service's port (the app gets PORT), the health page returns a status under 400, and look at Logs for crashes. A failed pre-deploy command also keeps the old version; its output is in History.

#HTTPS and domains

  • The DNS record must point at the server before a certificate can be issued. Fix it, then press Retry HTTPS.
  • dig +short <domain> should show the server's IP (or the CNAME then the IP).
  • Let's Encrypt allows about 50 new certificates per registered domain per week. If you hit it, wait, or spread services over more than one base domain.

#Email

If alerts or invites don't arrive, open Monitoring → Alerts → Save and send a test email. The error says whether the SMTP server, port or sign-in is wrong. Check spam folders and that the sender address is allowed by your provider.

#Backups

  • Press Test the bucket on the Backups page; it explains a wrong key, region or endpoint.
  • For R2, B2, Wasabi or MinIO, the Storage address under Advanced must be set.
  • The key needs to list, read, write and delete in the bucket.

#Databases

#The app can't write: "read-only transaction"

The database reached its quota. Raise it under the database's Settings or delete data; writes come back within 5 minutes.

#AWS plugin

  • AccessDenied on Costs: the key lacks the policy, or "IAM user and role access to Billing information" is off in the account settings.
  • "Cost Explorer has no data yet": turn it on under Billing; the first numbers take up to 24 hours.
  • Create server stuck at booting: the VM never called back. Check DEPLOYER_URL is public https://, then Discard and try again.

#The console itself

cd /opt/deployer
sudo docker compose ps
sudo docker compose logs --tail 200 app
sudo docker compose logs --tail 100 caddy

If you've lost every owner's two-step device, another owner can reset it under People. If there's no other owner, ask for help in a GitHub issue (don't post secrets).

#Known limits

  • One operation runs at a time across all servers (app builds run on GitHub, outside that queue).
  • While a new app version starts, the app is briefly unavailable.
  • Apps and images have no volumes yet; data belongs in a database.
  • Certificates are per address, within Let's Encrypt's weekly limits.
  • Default server folder and container prefix are /opt/avrosphere and avrosphere unless you set AGENT_ROOT and AGENT_NAMESPACE.
