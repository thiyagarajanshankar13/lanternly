Domains and HTTPS

Every service with a web address gets <name>.example.com with a free HTTPS certificate, and you can add as many custom domains as you like.

#Your base domain

Under Settings → Edit settings → Domain services live under, set the domain your wildcard DNS record points at (for example example.com). A service named shop then gets shop.example.com. Names like www, admin and api are reserved; add more under Branding → More reserved names.

A service's name, and so its base address, can't change after it's created. Add a custom domain instead.

#Add a custom domain

  1. At the domain's DNS provider, add one record:
    • for a subdomain such as www.shop.com or app.shop.com: a CNAME to the service's address (shop.example.com);
    • for a bare domain (shop.com): an A record to the server's public IP.
    The service's page shows both values.
  2. On the service's page, open More → Custom domain (or Add a custom domain), enter the domain and press Add domain. The console checks the record is in place first.
  3. The server asks Let's Encrypt for a certificate within a minute. That only works once DNS points at the server, so add the record first.

A bare domain and www. are two addresses: add the A record and the CNAME, then add each one on the service's page.

#Main address

The first custom domain becomes the service's main address. With several, press Make main to choose. The example.com address keeps working.

#When HTTPS doesn't work

If a domain was added before its DNS pointed at the server (with Add anyway, or the record changed later), visitors see a security error and the server waits longer before each new try. Once the record is right, press Retry HTTPS under Addresses and the server asks again straight away. The output lists which addresses have a certificate.

  • DNS changes can take a few minutes to an hour to appear.
  • If your own computer still shows the old site, it's remembering the old DNS record: try another device or mobile data, or wait.
  • Check the record from anywhere with dig +short www.shop.com.

#Certificate limits

Certificates are issued per address. Let's Encrypt allows about 50 new certificates a week per registered domain, so creating many services under one base domain in a single week can hit that limit. Monitoring warns 14 and 3 days before any certificate runs out (renewal is automatic, so a warning means something is wrong).

#The console's own address

The console's domain is set when you set up the deployer VM (DEPLOYER_DOMAIN). To move it, point the new name's DNS at the deployer VM and run setup-deployer-vm.sh again with the new DEPLOYER_DOMAIN: it rewrites Caddy's config and DEPLOYER_URL and reloads Caddy. Then restart the console with cd /opt/deployer && sudo docker compose up -d. If you use Connect GitHub, connect again so GitHub sends pushes to the new address.
