Run things

Docker images

Run an image someone has already built, such as nginx, redis or louislam/uptime-kuma, with no GitHub repo involved.

#Add an image service

  1. Open a project and press New service → Docker image.
  2. Image: a name and tag such as nginx:1.27, bitnami/redis:7.4, ghcr.io/owner/app:v2 or image@sha256:…, or paste the image's link from hub.docker.com. Pick a version tag rather than latest so every restart runs the same thing.
  3. Name: other services in the project reach it by this name.
  4. Private image (optional): a registry user name and a read-only access token (on Docker Hub: Account settings → Personal access tokens). Don't use your password. The token is stored encrypted and only used for each pull.
  5. Give it a web address: leave it ticked for a website. Untick it for things only the project uses, such as a cache or a worker: it then has no address on the internet and isn't monitored.
  6. Port: the port the image listens on (its Docker Hub page usually says: 80 for nginx, 6379 for Redis). Health page: a page that answers once it's ready, or empty when the image serves no web pages.
  7. Settings: the environment variables the image reads. Database links and ${{db.VAR}} references work as they do for apps.
  8. Press Create service. The image is pulled and started, usually in under a minute.

#Pinned to a digest

When an image is pulled, the server runs the exact digest it got and the console records it (Pinned to nginx@sha256:…). A tag that's later moved on Docker Hub doesn't change what's running until you ask for it.

  • Pull again fetches the tag again and starts what it points to now.
  • Versions lists each digest that has run, with Roll back.
  • Settings changes the image (pulling and starting the new one), the sign-in, web address, port, health page, memory and settings.

#Limits

  • No volumes yet: anything the container writes is lost when it restarts or updates. Keep data in a project database.
  • The image's own start command is used; there's no override.
