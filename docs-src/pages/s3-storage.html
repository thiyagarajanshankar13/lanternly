S3 storage is built and in review, and isn't in a release yet. This page describes how it will work so you can plan for it. Watch the repo for the release.

S3 storage gives a project its own S3-compatible bucket storage on its server, next to PostgreSQL, so apps can keep uploads and files without an outside service.

What you'll get

  • New service → S3 storage (MinIO). Its own container per storage, running a patched MinIO image pinned to the pulled digest, 256 MB of memory and no published port.
  • Buckets. Up to 20 per storage. Add one, remove an empty one, and choose who can read it: Apps only or Anyone with the link.
  • Optional web address with HTTPS, so browsers can open public files and signed links. It's monitored like any other address.
  • Keys made on the server and never stored by the console. Connect → Show values reads them over SSH and writes it to the access log. New keys rotates them and restarts the apps that use them.
  • Soft quota (10 GB by default) with emails at 80% and 100%. Writes are never stopped.
  • Backups and restore through the normal bucket backups.

Linking storage to an app

In the app's settings (the section becomes Databases and storage), tick the storage and pick a bucket. The app gets:

S3_ENDPOINT=http://shop-files:9000
S3_PUBLIC_URL=https://shop-files.example.com
S3_REGION=…
S3_BUCKET=uploads
S3_ACCESS_KEY_ID=…
S3_SECRET_ACCESS_KEY=…
S3_FORCE_PATH_STYLE=true

With no prefix it also gets the AWS_* names AWS SDKs read, so most S3 libraries work without code changes. ${{shop-files.S3_ENDPOINT}} references work too.

When it ships

Servers will need the new clubctl: run the services VM setup (or the Set up a VM workflow) again after upgrading. Until then, creating a storage fails with a clear message, and Try again works afterwards.
