Lanternly is a deploy console you host yourself. It runs web apps, Docker images and PostgreSQL databases on your own Linux servers, gives each one an HTTPS address, backs them up to any S3 bucket and tells you when something goes down.

Think of it as a small Railway or Render that lives on two VMs you control. You pay your cloud provider and nothing else: no seats, no usage meter, no data leaving your servers.

What you can do with it

  • Deploy from GitHub. Any repo and branch with a Dockerfile. Images are built on GitHub Actions, every push can deploy itself, and Roll back starts an earlier version without rebuilding. Apps from GitHub
  • Run any Docker image. Docker Hub, ghcr.io or a private registry, pinned to the exact digest that was pulled. Docker images
  • Group services into projects. Each project has its own private network: services find each other by name, and projects can't see each other. Projects
  • S3 storage on your own server. MinIO buckets per project, public or private, linked to apps with the usual S3_* and AWS_* settings. S3 storage
  • PostgreSQL, looked after. One tick links a database to an app. Password rotation, major-version upgrades with roll back, dumps, and a size quota with alerts. PostgreSQL
  • HTTPS and your own domains. Every service gets an address under your domain with a free certificate, and a CNAME adds a custom domain. Domains and HTTPS
  • Encrypted backups to any S3 bucket. AWS S3, Backblaze B2, Cloudflare R2, MinIO and others, encrypted before upload, on a schedule, restorable into a copy first. Backups
  • Monitoring with email alerts. For the services Lanternly runs and for sites hosted anywhere else. Monitoring
  • Team access. Owners, operators and viewers, per project or per service, with two-step sign-in for everyone and an access log. People and access
  • Plugins. Add service kinds, pages and settings without touching the core. The included AWS plugin creates Lightsail servers and reports costs. Plugins

How it works in one picture

The console never gets a shell on your servers. Its SSH key is locked to one program, clubctl, which accepts a fixed list of commands and checks every argument. More in How it fits together and Security.

What you need

  • Two Ubuntu 24.04 VMs with a static IP and ports 22, 80 and 443 open: a small one for the console (2 GB) and one or more for your services (4 GB or more). Any provider works.
  • A domain whose DNS you control.
  • A GitHub account, if you want to deploy from repos.
  • An S3-compatible bucket, if you want backups.
